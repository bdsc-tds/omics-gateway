# Vitessce build patches

The build patches Vitessce's prebuilt code as it reads it. Each patch in `vite.config.js` replaces one exact snippet of `node_modules/vitessce/dist/` with a change or a call into `vitessce_patches.js`. This file lists every patch by its name in `vite.config.js`, says what it changes and why, and gives a readable string to search for after an upgrade, since the snippets themselves contain names that Vitessce's build minified (see [Rebuilding the spatial viewer](../README.md#rebuilding-the-spatial-viewer) for the upgrade procedure). Every snippet is in Vitessce's main chunk, `index-<hash>.js`, close to the string given for it.

## Loading and speed

* **parquet-wasm**: Vitessce loads its Parquet reader, a custom build of [parquet-wasm](https://github.com/kylebarron/parquet-wasm), from `cdn.vitessce.io`; the patch loads the copy vendored in `omics_gateway/static/vendor/parquet-wasm-<build>/` instead. Search for `cdn.vitessce.io`.
* **gene mapping**: Vitessce fetches a table mapping Ensembl gene IDs to gene symbols from `data-1.vitessce.io`; the patch loads the copy vendored in `omics_gateway/static/vendor/vitessce-data-<date>/` instead. Search for `data-1.vitessce.io`.
* **matrix arrays retry**: the AnnData loader opens the arrays of a sparse expression matrix once and keeps the promise; if that download fails, the failed promise is now forgotten, so the next gene selection downloads the arrays again instead of failing until the page is reloaded. Search for `sparseArrays`.
* **matrix CSR retry**: the same for the dense copy of a CSR matrix, which the loader builds on the first gene selection. Search for `_loadCSRGeneSelection` (the first match); the snippet follows it.
* **point hidden no fetch**: deck.gl loads the tiles of invisible layers too, so a hidden Transcript layer kept downloading transcripts as the view moved; it now returns empty tiles while hidden. Search for `obsPointsFeatureIndices`.
* **point visibility reload**: makes the Transcript layer's visibility one of the triggers that reload its tiles, so showing the layer replaces the empty tiles that **point hidden no fetch** gave it while hidden. Search for `loadedTiles`.
* **point rect clamp**: a tile reaching past the far edge of the transcript data gave a lookup rectangle with corners beyond the Morton grid, and the loader threw `Rectangle out of bounds`; the corners are now clamped to the grid's largest coordinate, as Vitessce already clamps them to zero at the low end. Search for `Clamp to zero at low end`.
* **point min zoom**: Vitessce loads transcripts only from zoom -1 inward, so they vanished as soon as the view was zoomed out a little. They now load down to `POINT_MIN_ZOOM` in `vite.config.js` (-3). Every transcript in view downloads, whatever the gene, so zoomed out to -3 the whole transcript file of a sample may download; lower values made the browser tab lag or freeze. Search for `no benefit to request tiles`.
* **point min size**: transcripts are drawn at least one pixel wide, since their radius is in image units and shrank to nothing when zoomed out. Search for `// getPosition: d => d`; the snippet sits just above it.
* **point tile lookups**: a tile is split into squares of 256 image units, and each square costs one search of the row groups, which rescans the loaded data each time; the larger tiles of **point min zoom** now split into at most 4×4 squares, so zooming out stays fast. Search for `loadParquetTableInRect` (the first match).
* **point row group clamp**: a Morton code past the maximum of the last row group made the search for its row group return one index past the last; it now returns the last row group. Search for `_rectToRowGroupIndices`.
* **row-group extents**: to find which transcript row groups a tile needs, Vitessce searches them one after another, downloading each row group it checks in full just to read its first and last Morton code. The patch reads those values from the minimum and maximum statistics in the Parquet file's footer, which the browser has already downloaded, so only the row groups shown are fetched, all at once. If the statistics are missing (pyarrow writes them by default), Vitessce's own search runs and the browser console shows `No footer statistics for …`. Search for `_loadParquetRowGroupColumnExtent`.
* **queries never stale**: loaded data is kept for the whole visit, so a view shown later (such as a tab switch) does not load it again and flash every view's loading state; failed loads are still retried. Search for `refetchOnWindowFocus`.

## Display

* **missing expression**: in a sample's config, the Merged UMAP shows the cells of every sample, while the expression matrix holds only this sample's. Vitessce read the other samples' cells' values from matrix rows that do not exist; they now get -1, which **missing expression colour** recognises. Search for `instanceObsIndex` (the first match).
* **missing expression colour**: the shader that colours scatterplot points by expression now does so only when a point's value is not negative, so the cells marked by **missing expression** keep their own colour (the default grey while cells are coloured by a gene) instead of a colour on the gene's scale. Search for `"scaled-expression"`, with its quotes.
* **set colours**: cell sets named `Unassigned` are drawn mid grey instead of taking a palette colour, darker than the light grey of unselected cells. In a sample of a multi-sample store, the other sets take their colours from the order of the all-samples table, which `data_prep/generate_spatial_config.py` writes into the config's `gatewayOptions.setOrder`, so a cell type or cluster keeps its colour in every sample even when another sample lacks some sets. Search for `Need to add one because its an array`.
* **set colours complete**: when a config already holds set colours (the viewer carries them over on a sample switch), sets missing from them get Vitessce's colours instead of none. Search for `ZarrNodeNotFoundError`; the snippet follows it.
* **scatterplot set legend**: UMAPs coloured by cell sets show a legend of those sets, as the spatial view does; Vitessce gave the scatterplot's legend no set colours, so it showed only gene colour bars. Search for `obsEmbeddingX` (the second match).
* **scatterplot waits for sets**: a scatterplot whose config already selects cell sets (UMAP by Sample) no longer sorts its cells into them before the sets have loaded, which logged "The final insertion index is lower than expected" once per set. Search for `obsEmbeddingX` (the second match).
* **crosshair position**: the crosshair a spatial view draws for a cell hovered in another view (such as the UMAP) sat below the cell, by the offset Vitessce uses to stack tooltips (about 15 px per tooltip row), which is far when zoomed out; it now sits on the cell. Search for `Pixel Value`.
* **dot plot height**: the dot plot grows taller with each selected gene, so its circles no longer overlap. Search for `shift_dot_select`.
* **point colours**: transcripts are coloured per gene in *Feature Color* mode, whose colour squares can be edited; each gene gets its palette colour when first selected, so configs store no colour list. Search for `spatialTiledPointsLoadingProgress` (the second match).
* **point sub-rows visible**: the per-gene rows under *Transcript* in the layer controller appear only while the Transcript layer is visible. Search for `Toggle visibility of unselected points`.
* **scale bar size**: Vitessce's spatial view labels one unit of the image as 1 µm, but the gateway's stores measure in image pixels. The bar now takes its scale from the config's `gatewayOptions.micronsPerUnit`, which `data_prep/generate_spatial_config.py` writes and `main.js` removes before Vitessce reads the config; without it the bar is hidden rather than wrong. Search for `scalebar-layer`.
* **scale bar colour**: the bar is drawn black on a translucent white box, instead of light grey on nothing, so it reads on fluorescence and H&E images alike. Search for `"ScaleBarLayer"`, with its quotes.

## Interaction

* **scatterplot hide tools**: a scatterplot's `hideTools` prop hides its pointer and lasso buttons, as for spatial views; the study config's UMAP by Sample uses it, since a lasso there would replace its sample colouring. Search for `obsEmbeddingX` (the second match).
* **gene chips clear**: passes the gene list's plain selection setter to the list as well as its own, which also switches the cells' colouring to gene expression. **gene chips** uses it for *Clear*, so clearing the genes leaves the colouring alone. Search for `setGeneFilter`.
* **gene chips**: the gene list gets a row of the selected genes, between the search box and the table, with buttons to remove one or clear them all; the table shrinks to make room. Search for `columnLabels` (the second match).
* **click toggles**: a plain click on a gene adds it to the selection or removes it, also among search results; Shift+click keeps only the clicked gene. Search for `selectableTable`; the snippet sits between its two matches.
* **solo click hidden genes**: Shift+click also drops selected genes the search hides. Search for `Alternate ID`.
* **set buttons setter**: passes the Cell Sets view's selection setter to its sets manager, for the *None* button of **set buttons**. Search for `onCheckLevel` (the last match).
* **set buttons**: the Cell Sets toolbar gets *All*, which ticks every set of the hierarchy last ticked (or the first one), and *None*, which clears the selection to an empty list. Search for `setOperationButtons`.
* **auto-fill**: cells are filled when they switch to gene colouring and back to outlines when they switch away; ticking *Filled* by hand still works in between. Search for `setSpatialRotationZ` (the first match).

## Internals

* **view internals**: exports the hooks and components that the gateway's own views (`gateway_views.js`) need (data loading, the panel title bar, coordination types), which the `vitessce` package does not export. They are imported through the `gateway-vitessce-internals` alias, which `vite.config.js` points at the main chunk by its file name: update `VITESSCE_CHUNK` after each upgrade. The snippet is the chunk's final `export` statement; search for `Unrecognized URL Param Version` just above it.
